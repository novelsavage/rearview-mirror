# PCバックミラーアプリ企画書

作成日: 2026-07-28
仮称: Rearview Mirror

## 1. 結論

このアプリは、ノートPCの内蔵Webカメラに映る「利用者の肩越しの後方」を、小さな常時手前表示ウィンドウで数秒だけ確認するWindowsアプリとする。

最初に作るべきものは高機能な監視アプリではなく、次の体験だけに絞ったMVPである。

1. ショートカットを押している間だけ、小さなミラー映像が表示される
2. 離すと即座に隠れ、カメラも停止する
3. 初回だけ、後方が見えるように拡大率と表示範囲を調整できる
4. 録画、撮影、音声取得、クラウド通信は一切行わない

技術は `Rust + Tauri 2 + Vanilla TypeScript` を推奨する。Tauriの公式グローバルショートカットは押下と解放を区別できるため、「押している間だけ表示」をOS全体のキー入力監視なしで実現できる。ウィンドウ制御はRust側、カメラプレビューとクロップはWebView側に分ける。

## 2. 解決したいニーズ

### 想定ユーザー

- 大講義室の前方に座る大学生
- 後方の混雑、知人の位置、退出の様子などを一瞬確認したい人
- 振り向く動作によって周囲の注目を集めたくない人
- 講義資料を表示したまま、操作を最小限にしたい人

### Jobs to be Done

> 講義中に後方の状況が気になったとき、振り向いて周囲の視線を集めずに、PC画面上で数秒だけ後方を確認したい。

### 中核ニーズ

| 優先度 | ニーズ | 設計への反映 |
|---|---|---|
| Must | 目立つ身体動作なしで後方を確認したい | 内蔵カメラのライブプレビュー |
| Must | 操作自体も目立たせたくない | 押している間だけ表示するショートカット |
| Must | 講義資料を邪魔されたくない | 小型・常時手前・位置記憶 |
| Must | 他人を記録したくない／されたくない | プレビューのみ、録画・撮影・音声なし |
| Must | カメラを使い続けたくない | 非表示時はストリームを停止・解放 |
| Should | 自分の顔や肩を避けて後方だけ見たい | デジタルズームとクロップ位置調整 |
| Should | 左右を直感的に把握したい | 初期値は水平反転、設定で解除可能 |
| Could | 暗い講義室でも見たい | 明るさ・コントラスト補正 |

### 解決しないこと

- 監視、証拠収集、防犯カメラ用途
- 録画、静止画保存、人物認識、顔認識
- 他人に気づかれないようカメラ使用表示を隠すこと
- 遠隔配信、クラウド保存、分析

## 3. 成立条件と最大の不確実性

ノートPCのカメラは利用者を正面から撮るため、その背景として後方の座席が映る。ただし、次の条件で実用性が大きく変わる。

- 画面の開き角度とカメラの画角
- 利用者の頭・肩が後方をどの程度遮るか
- 前席との高低差
- 暗さ、逆光、カメラ解像度
- 講義資料の表示領域をどの程度奪うか

最大のリスクは「技術的に映るが、必要な範囲が身体で隠れて役に立たない」ことである。したがって、実装前に実機のカメラ映像をWindows標準カメラアプリで確認し、3種類以上の座席・画面角度で後方の見え方を試す。この検証を通らなければ、ソフトウェア開発より先に外付け広角カメラや物理ミラーを再検討する。

## 4. MVPのUX

### 基本フロー

1. 初回起動
2. カメラ使用目的を一文で説明し、ユーザー操作で権限を要求
3. カメラを選択
4. プレビュー上で拡大率と縦横位置を調整
5. ミラー反転の有無、ウィンドウ位置、ショートカットを確認
6. 設定完了後は待機
7. ショートカットを押している間だけ映像を表示
8. キーを離す、または `Esc` で即時非表示・カメラ解放

### 画面仕様

- 通常サイズ: 長辺180 px、初期アスペクト比16:9のため **180 × 101 px**
- サイズ: 設定画面で長辺120〜1,000 pxの範囲に変更可能。プリセットは120 / 180 / 240 / 320 px
- 配置: 初回は右上。最後に確定した位置を保存する
- 装飾: **カメラ映像だけ**。境界線、タイトルバー、ボタン、ステータス表示はミラー画面に出さない
- ウィンドウ: 枠なし、常に手前、タスクバーには表示しない
- 反転: 水平反転を初期値とし、設定で切替
- クロップ: 1.0〜2.5倍の拡大と表示中心の移動
- エラー: 権限拒否、カメラ競合、切断を区別し、Windows設定への導線を出す

### 設定画面への導線

設定は**タスクトレイのアイコンを右クリックして「設定」**から開く。ミラー画面に設定ボタンを置かないため、普段の確認中は映像以外が一切見えない。

- 初回起動: 設定画面を開き、カメラ選択・プライバシー説明・ショートカットを案内する
- 2回目以降: ミラーは隠したままトレイに常駐する
- トレイメニュー: `ミラーを表示` / `設定` / `Windows起動時に開始` / `終了`
- 緊急時: `Esc` でミラーを隠す。設定を開く必要がある場合はトレイに戻る

右クリックのような映像上の隠し操作は、誤操作と発見しにくさを増やすためMVPでは入れない。

### 操作方式

体験としての第一候補は「押している間だけ表示」である。トグル式より消し忘れが起きにくく、確認行動が短くなる。

- `Ctrl + Alt + Space` 長押し: 表示
- キーを離す: 非表示
- `Esc`: 緊急非表示
- 設定でトグル式にも変更可能

ショートカットを押したままマウスを動かすと、ミラーウィンドウも同じ移動量だけ追従する。これはクリックやドラッグを必要としない位置調整である。

1. ショートカット押下時に、マウスの画面座標とミラーの左上座標を記録する
2. 押している間、マウスの移動差分をミラーの位置へ加算する
3. キーを離した位置を保存し、次回表示時に使う

トラックパッドの微小な揺れで位置が動くことを避けるため、最初の4 pxは移動として扱わない。設定には `ショートカット中のマウス移動で位置を変える` と `位置を固定` を用意し、前者を初期値オンにする。

ショートカットはPowerPoint、ブラウザ、IDEなどとの競合を実機で確認してから確定する。

Tauri 2の公式 `global-shortcut` プラグインは `Pressed` と `Released` を区別できる。Rust側で登録し、押下時にウィンドウへ開始イベント、解放時に停止イベントを送る。これにより低レベルキーボードフックでOS全体の入力を監視せずに長押し方式を実装できる。ショートカットが他アプリに取得されている場合は登録失敗を明示し、設定変更を促す。

## 5. プライバシーと倫理

大学の講義室で他人が映り込むため、「目立たないUI」と「隠し撮り」は明確に分ける。

- 映像フレームをファイル、クリップボード、ログへ保存しない
- マイク権限を要求しない
- ネットワーク通信を持たない
- 非表示時はプレビューを止め、カメラデバイスを解放する
- カメラ利用中はアプリ内表示とWindowsのカメラ表示を妨げない
- 初回画面で、所属大学・講義のルールと周囲のプライバシーへの配慮を案内する
- 録画・人物認識は将来候補にも入れない

「離した瞬間に停止」を成立させるため、単にウィンドウを隠すのではなく、すべての `MediaStreamTrack` に `stop()` を呼び、`video.srcObject` を解除してからウィンドウを隠す。WebView2を含むカメラ実装は、ウィンドウを隠したこと自体をカメラ解放の保証にしない。

## 6. 技術選定

### 採用案

| 領域 | 選定 |
|---|---|
| 対象OS | Windows 10 / 11、最初の検証対象はWindows 11 |
| バックエンド | Rust stable |
| アプリ基盤 | Tauri 2の実装開始時点の最新Stable |
| フロントエンド | Vanilla TypeScript + Vite + CSS |
| カメラ | `navigator.mediaDevices.getUserMedia()`、音声は常に無効 |
| 表示 | HTML `video` + CSS `transform` / `object-position` |
| ショートカット | `tauri-plugin-global-shortcut` |
| ウィンドウ | Tauri Window APIの `show` / `hide` / `alwaysOnTop` / `setPosition` |
| マウス追従 | Rust側で押下中だけ画面座標を取得し、差分を `setPosition` へ反映 |
| 常駐 | Tauriのトレイアイコン。起動時自動開始はユーザーが明示的にオンにした場合のみ |
| 設定保存 | `tauri-plugin-store`。映像は保存しない |
| 配布 | 初期はNSIS形式のWindowsインストーラー |
| テスト | Rust単体テスト + TypeScript単体テスト + 手動カメラ／ライフサイクル試験 |

実装時はTauri本体と公式プラグインの最新Stableを確認し、`Cargo.lock` とフロントエンドのロックファイルで固定する。

### 選定理由

- 公式ショートカットプラグインが `Pressed` / `Released` を通知するため、長押しUIと一致する
- Tauri Window APIで表示、非表示、常時手前を扱える
- WindowsではOSのWebView2を利用し、ElectronのようにChromium全体を同梱しない
- カメラ表示、水平反転、クロップはWeb標準APIとCSSだけで実装できる
- 権限ファイルで、フロントエンドから呼べるTauriコマンドを必要最小限に限定できる
- 将来クロスプラットフォーム化するときも、UIの大部分を再利用できる

### Tauri案で先に検証する点

- 開発時URLだけでなく、パッケージ後のTauriカスタムプロトコルでも `getUserMedia()` が動作すること
- Windows/WebView2のカメラ許可UI、拒否後の再案内、企業・大学PCのポリシー制限
- `Released` イベントが、キーリピートや別アプリへのフォーカス移動後も一度だけ確実に届くこと
- `track.stop()` 後にWindowsのカメラ利用表示が消えること
- ウィンドウ再表示のたびにカメラを初期化した場合の待ち時間

この5点が技術スパイクを通らない場合のみ、カメラ層をRustのネイティブ実装、またはWinUI 3へ切り替える。最初からRustで映像フレームを取得してWebViewへ転送する構成は、コピーと画像変換が増えるためMVPでは採用しない。

### 不採用案

| 案 | 長所 | 今回見送る理由 |
|---|---|---|
| ブラウザ/PWA | 最速で試せる | 常時手前、グローバル長押し、非表示時のライフサイクルが弱い |
| Electron | Web技術で実装しやすい | 単機能アプリにはランタイムとメモリ負荷が大きい |
| Python + OpenCV | 画像処理を試しやすい | カメラ競合、配布、Windowsらしい権限・ウィンドウ制御の作り込みが増える |
| WinUI 3 | カメラとウィンドウが完全にWindowsネイティブ | 長押しショートカットを含め、Tauriの公式機能だけでMVP要件を満たせる見込みが高い |

## 7. アーキテクチャ

```text
Rust / Tauri
  GlobalShortcutPlugin
        │ Pressed / Released event
        ▼
  MirrorSessionController ─────► WindowController
        │                         └─ show / hide / always-on-top / position
        │
        ├────────────────────────► PointerMoveController
        │                         └─ shortcut押下中のカーソル差分 → position
        │ Tauri event
        ▼
WebView / TypeScript
  CameraController ────────────► VideoView
        │                         └─ mirror / crop / zoom
        ├─ getUserMedia
        ├─ MediaStreamTrack.stop
        └─ permission / device error

  SettingsStore
    └─ camera ID, crop, mirror, window position, shortcut
```

`MirrorSessionController` を中心に「Hidden → Starting → Visible → Stopping → Hidden」という状態遷移を明示する。ショートカット連打やカメラ起動中の再入力でも二重初期化しないようにする。

## 8. 非機能要件

- 表示要求から映像表示まで: ウォーム起動で500 ms以内を目標
- 非表示操作からウィンドウ消失: 100 ms以内を目標
- 非表示後のカメラ解放: 1秒以内
- 初期映像: 640 × 360 または 1280 × 720、15 fpsを基本に実機調整
- ネットワーク通信: 0件
- 保存される個人データ: 0件
- 待機中CPU: ほぼ0%
- カメラ利用中CPU: 対象PCで計測し、講義資料との同時利用に支障がないこと

速度目標は仮説であり、内蔵カメラの初期化時間を実測して調整する。カメラを常時保持すれば高速化できるが、プライバシーとバッテリーを優先し採用しない。

## 9. 開発フェーズ

### Phase 0: ニーズ検証（0.5〜1日）

- Windows標準カメラアプリで講義室に近い配置を再現
- 画面角度、座席高低差、明るさを変えて後方の視認性を記録
- 5秒以内の確認で知りたい情報が得られるか確認
- 他の学生3〜5人に、使いたい場面と不安点をインタビュー

Go条件: 3つ以上の想定配置で後方の必要範囲が見え、利用者の過半数が「録画なしなら試したい」と回答する。

### Phase 1: 技術スパイク（1〜2日）

- 1台のカメラを選択してプレビュー
- 水平反転、クロップ、ズーム
- 常時手前ウィンドウの表示・非表示
- `Pressed` / `Released` によるグローバル長押し操作
- 枠なし・映像のみの600 × 338 pxウィンドウ
- 長押し中のマウス追従、位置保存、画面端での見切れ防止
- トレイから設定画面を開く
- 開発ビルドとパッケージ済みビルドの両方でカメラ権限を確認
- 停止後にWindowsのカメラ利用状態が消えることを確認
- Zoom、Teams、標準カメラとの競合時の挙動を確認

Go条件: 10回連続の表示・非表示でハングせず、毎回1秒以内にカメラを解放する。

### Phase 2: MVP（3〜5日）

- 初回権限導線
- 設定画面
- 長押しショートカット
- サイズ・位置・クロップ・反転の保存
- トレイ常駐と、設定画面からのWindows起動時自動開始
- エラー表示と緊急非表示
- ログに映像やデバイス名を残さない

### Phase 3: 実地評価（1週間）

- 講義前後など、撮影ルールを確認できる環境で試験
- 表示速度、見え方、消し忘れ、バッテリー影響を記録
- 誤操作とショートカット競合を収集

### Phase 4: v1

- MSIX配布
- 署名とアンインストール確認
- 複数カメラ、外付けカメラ切断への対応
- アクセシビリティと高DPI・複数ディスプレイ試験

## 10. MVPの受け入れ基準

- 初回以外は、ショートカット一つで確認を開始できる
- 長押しを離すと即座に画面が消える
- 非表示後、Windows上でカメラが使用中になり続けない
- 自分の肩を避けるクロップ設定を保存できる
- 左右反転を切り替えられる
- カメラ拒否時にクラッシュせず、Windows設定への案内が出る
- 別アプリがカメラ使用中でもクラッシュしない
- アプリ終了後にカメラプロセスやバックグラウンド処理が残らない
- 音声・画像・映像・通信ログを一切生成しない

## 11. 検証したい質問

1. 後ろで何を確認したいのか。人の位置、混雑、退出、視線のどれか
2. 何秒見えれば目的を果たせるか
3. 常時表示と長押し表示のどちらが自然か
4. 360 × 203 pxで十分か
5. 水平反転は直感的か、それとも実際の左右関係を混乱させるか
6. カメラ使用への心理的抵抗は、録画なしの説明で下がるか
7. 大学や講義ごとのルール上、ライブプレビューは許容されるか

## 12. 成功指標

MVPの成功はダウンロード数ではなく、次で判断する。

- 5回中4回以上、3秒以内に後方確認を開始できる
- 1回の確認が平均10秒未満で終わる
- 非表示後のカメラ解放成功率100%
- テスト利用者の80%以上が「振り向くより気にならない」と回答
- テスト中の誤録画・データ保存・意図しない通信0件

## 13. 将来候補

ニーズが確認できた後だけ検討する。

- 外付け広角Webカメラ向けプリセット
- 明るさ・コントラストの手動補正
- ウィンドウサイズのプリセット
- 画面端へのスナップ
- キーボード以外の操作（マウスサイドボタン等）

人物検出、視線検出、顔認識、録画はスコープ外のままとする。
